# 用户、角色与账号关联

[English](/features/users-bilingual)

本指南适用于社区维护仓库 `CM-Chenqf/headplane-zh-cn` 的 **0.8 发布线**，基于上游 [tale/headplane](https://github.com/tale/headplane)，**不是 Headplane、Headscale 或 Tailscale 官方中文版**。保留上游 MIT 许可证及原作者版权声明。其他模块汉化和发布验收仍在进行，详见[语言与维护说明](/zh-CN/features/language)。

## 区分两类用户

**Headplane 账号**是本地保存的登录身份，拥有角色，并可关联一个 Headscale 用户。**Headscale 用户**由 Headscale API 提供，用于拥有设备。创建 Headscale 用户不会创建 Headplane 登录身份，也不会授予角色。

用户页优先列出 Headplane 账号，展示角色、最近登录、关联身份、设备状态和策略用户组；未关联本地账号的 Headscale 用户单独列出。Headscale 不可用时会显示错误，但仍保留本地 Headplane 账号列表，设备信息和未关联用户列表暂时不可用。

两种语言均保留姓名、电子邮箱、标识符、用户组名称及原始 API 诊断值，日期按所选界面语言显示。API 密钥会话的权限行为沿用上游。

## 创建、重命名与删除

1. 使用具有用户管理权限的账号进入**用户**页，选择**添加用户**。
2. 填写用户名，可选填显示名称和电子邮箱。用户名至少两个字符，以 Unicode 字母开头，可包含字母、十进制数字、点、连字符和下划线；最多包含一个 `@`，且不能以 `@` 结尾。原有规则支持汉字。
3. 确认后在 Headscale 中创建用户，关联 Headplane 账号前会显示在未关联列表中。自动匹配取决于原有认证配置及身份信息，创建用户本身不保证自动匹配成功。

具有相应权限时，可从未关联 Headscale 用户的菜单重命名或删除用户。OIDC 管理的 Headscale 用户不能在此重命名。重命名不会更新引用旧用户名的 ACL 策略，需另行核对策略引用。

删除用户前，先删除其全部设备或更改设备所有者。用户删除后无法恢复。删除已关联的 Headscale 用户会解除本地 Headplane 账号的关联，**不会删除本地登录账号**。通过外部身份提供商认证的用户可能在再次登录时重新创建。账号菜单不提供删除自己的操作。

## 角色与所有权

角色显示名称会翻译，存储的角色标识和能力保持不变。下表基于 0.8 的实际能力定义，不等同于 Tailscale 托管服务的角色说明。

| `owner`（所有者）             | 可访问     | 可以           | 可以           | 完整管理及转移所有权                                            |
| `admin`（管理员）             | 可访问     | 可以           | 可以           | 除转移所有权外的完整管理                                        |

未关联账号的更改角色操作不可用。打开所有者的角色弹窗时会显示说明，不显示角色选择器。只有当前所有者可以向其他账号转移所有权；转移后，目标账号成为所有者，原所有者降为管理员，请谨慎操作。

## 关联账号

管理员可从 Headplane 账号菜单选择**关联 Headscale 用户**或**更改关联用户**。候选项包含尚未被占用的 Headscale 用户和该账号当前的关联，排除已关联其他账号的用户。发生并发占用时会返回冲突，不会接管其他账号的关联。

0.8 的自助关联入口是**登录后的首页**，并非独立的 `/link` 路由。自动匹配失败且存在未关联用户时，首页要求选择 Headscale 用户，提交后返回首页。仅选择属于当前登录人的身份；此选择页没有跳过按钮。如果看不到预期用户，请联系管理员，并核对 Headscale 与 SSO 的电子邮箱是否匹配。

## 编辑策略用户组

编辑用户组需要同时具有用户管理及策略写入能力，并要求策略可写。文件模式或无法读取策略时，不显示此操作。可点击现有用户组建议，或输入有效的 `group:` 名称。移除标签仅修改该用户的组成员关系，不会重命名用户组或修改用户标识。

用户组保存在 ACL 策略的 `groups` 部分。**保存会重写策略并移除 HuJSON 注释。** 确认前保留备份并阅读警告。只读错误会说明 Headscale 原有的 `policy.mode: database` 要求；用户组名称和解析器／API 原始诊断继续保留。本阶段不包含独立访问控制编辑器的汉化。

## 无控制台权限的成员

账号认证成功但没有控制台权限时，页面会提供 Linux 安装命令及 Windows、macOS、iOS、Android 的 Tailscale 下载入口；已关联账号还会显示关联的 Headscale 用户名。未关联账号是否显示联系管理员的提示，取决于原有 OIDC 配置。访问控制台仍需相应角色。

0.8 此页面提供下载和安装说明，不会生成针对部署地址的 `tailscale up` 命令，请继续遵循部署环境原有的 Headscale 接入说明。下载地址、平台／版本标签及 Linux 命令保持不变。文档其他位置的上游截图仍为英文示意，待文档阶段复核。

## 验收与维护

验收两种语言、无效用户名与邮箱、必选项、角色限制、已占用用户过滤和策略注释警告。切换语言时，本地表单错误跟随语言变化，并保留草稿值。API 集成测试使用本发布线原有的 Headscale 版本矩阵，运行真实 Headscale，并使用内存数据库中的真实认证服务。

执行 `pnpm i18n:check`、`pnpm test:unit`、`pnpm typecheck`、`pnpm lint` 和 `pnpm docs:build`。集成测试需要项目的 Docker 环境。根路径及 `/0.8/` 文档归档会分别检查。本模块检查通过不代表完整汉化、Docker 发布已获验收。
