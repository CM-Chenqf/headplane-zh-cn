# Language and maintenance

This feature belongs to the community-maintained `CM-Chenqf/headplane-zh-cn` fork of [tale/headplane](https://github.com/tale/headplane) on `main`. It is not an official Chinese release of Headplane, Headscale, or Tailscale. The upstream MIT license and copyright notices are retained.

A complete bilingual image has not been published, and the bilingual documentation site has not been deployed. The `release/0.8` line translates language preferences, sign-in, shared UI, Machines, Users, roles, account linking and member downloads, with bilingual guides for the adapted features. Access Control, DNS, Settings, Browser SSH and full documentation are still incomplete on that line. Its original home-page account picker, permissions, username rules and compatibility requirements are preserved. Build and release status must be checked before deploying the fork.

## Interface language

Select **简体中文** or **English** in the sign-in or dashboard header. The selection is saved in the `headplane_locale` browser cookie for one year and applies before and after sign-in. It does not change the account, permissions, Headscale configuration or other browsers.

On the first visit, `Accept-Language` selects English or Simplified Chinese. Chinese language variants use Simplified Chinese; unsupported languages fall back to English. Clear `headplane_locale` to follow the browser preference again.

Sign-in, shared navigation, Machines, Users, Access Control, DNS, Settings and Browser SSH support both languages. These include forms, validation, action results, connection notices, shared errors, dates and relative times. See the [Machines](/features/machines-bilingual), [Users](/features/users-bilingual), [Access Control](/features/acls-bilingual), [DNS](/features/dns-bilingual), [Settings](/features/settings-bilingual) and [Browser SSH](/features/ssh-bilingual) guides.

Configuration keys, API fields, commands, product names, user-provided values, remote terminal output and original diagnostics retain their spelling. Chinese errors include explanations alongside original diagnostic details. Changing language does not change the time zone or recreate an SSH session.

## Documentation language

Choose **中文** or **EN** in the documentation header. English keeps the original URLs; Chinese pages live under `/zh-CN/`. Archived builds keep their version prefix, for example `/0.8/zh-CN/install/docker`. Switching language keeps the current page, query and fragment. Documentation language follows the URL independently of the application cookie.

Navigation, page content, search results, release history and upgrade notes follow the selected language. Search uses the real bilingual index and filters by language. Chinese headings retain the English reference anchors where the source pages use them. Screenshots reused from upstream are labeled as English screenshots; they are not Chinese interface captures.

In-app documentation buttons continue to open the upstream English site until the maintained documentation site is deployed. Installation examples that use upstream images or flakes are explicitly identified; they do not imply those artifacts contain this fork's translations.

## Maintaining interface translations

Add English messages in `app/i18n/en.ts` and Simplified Chinese in `app/i18n/zh-CN.ts`. Module resources such as `en/machines.ts` and `zh-CN/machines.ts` are re-exported there. TypeScript checks message keys; unit tests and the translation check validate matching interpolation placeholders.

Use `useI18n()` in React and `getLocale(request)` with `translate()` in server actions. Use `Message` for sentences with inline code or styled names so the whole sentence can be reordered. Pass the locale to time formatters. Keep request languages isolated; do not store a user's language in a process-wide variable.

## Maintaining documentation

Keep English source files and their `.zh-CN.md` or `.zh-CN.mdx` counterparts together. Each folder's `meta.json` and `meta.zh-CN.json` define navigation. Use site-path links such as `/install/docker`; the renderer applies the language and React Router adds any version prefix. Keep commands, identifiers and configuration values unchanged. Version values come from `docs/app/lib/versions.ts`.

Use `[#english-anchor]` on translated headings to retain inbound links and language-switch fragments. Update both `CHANGELOG.md` and `CHANGELOG.zh-CN.md`, preserving version headings, dates, references and the `Upgrading`, `Changes`, `Fixes` section markers used by the release parser. The renderer translates those section labels.

## Checking translation updates

Run `pnpm i18n:check` before committing. The **Translations** workflow runs the same check for pull requests and pushes to maintained branches. It checks missing or empty messages, placeholders, paired documentation, navigation order, release markers and common hardcoded UI messages, including accessible labels, object labels, toasts and `ActionError` text.

Review fingerprints in `.github/i18n/reviewed.json` cover each English/Chinese message pair, document pair and shared documentation source. Changing only English still requires review. A shared documentation code change is a review reminder; it does not necessarily mean its Chinese text is wrong. The check never updates these records.

Review the diff, translate any changed meaning, preserve commands and configuration values, then record only the reviewed entries:

```bash
pnpm i18n:review --message common.dismiss
pnpm i18n:review --file docs/install/docker.mdx
pnpm i18n:review --file docs/app/components/header.tsx
pnpm i18n:check
```

Use the English path for document pairs; options can be repeated. Reviewing one entry does not approve other changes. Deleted sources require removing the corresponding Chinese file and explicitly reviewing the old English path or message key to remove its record. Apply formatting before reviewing. The initial `--initialize` option refuses to replace an existing baseline.

Technical names and examples are listed in `.github/i18n/exceptions.json` with an exact message key or file and code text, plus a reason. Unused exceptions fail the check. Review new exceptions individually; do not bypass failures with broad exclusions or refresh all fingerprints without reviewing translations.

Static checks cannot prove translation quality or follow every dynamic string, third-party component or remote terminal message. Manually review source changes and both language flows; original server diagnostics remain untranslated alongside Chinese explanations. The audit scope is documented in `.github/I18N_AUDIT.zh-CN.md`.

Upstream updates open synchronization PRs and a tracking Issue with translation work and these review commands. Reminders do not complete translation or prevent merging by themselves; configure required status checks in GitHub branch protection if needed. Release-line adaptation, Docker publication and Cloudflare deployment remain separate acceptance steps. Deployment configuration is documented in `.github/FORK_SETUP.zh-CN.md` in the repository.
