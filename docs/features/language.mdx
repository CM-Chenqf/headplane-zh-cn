# Language and maintenance

This feature belongs to the `CM-Chenqf/headscale-web` fork on `main`. A complete bilingual image has not been published, the bilingual documentation site has not been deployed, and the `release/0.8` line has not yet been adapted. Build and release status must be checked before deploying the fork.

## Interface language

Select **简体中文** or **English** in the sign-in or dashboard header. The selection is saved in the `headplane_locale` browser cookie for one year and applies before and after sign-in. It does not change the account, permissions, Headscale configuration or other browsers.

On the first visit, `Accept-Language` selects English or Simplified Chinese. Chinese language variants use Simplified Chinese; unsupported languages fall back to English. Clear `headplane_locale` to follow the browser preference again.

Sign-in, shared navigation, Machines, Users, Access Control, DNS, Settings and Browser SSH support both languages. These include forms, validation, action results, connection notices, shared errors, dates and relative times. See the [Machines](/features/machines-bilingual), [Users](/features/users-bilingual), [Access Control](/features/acls-bilingual), [DNS](/features/dns-bilingual), [Settings](/features/settings-bilingual) and [Browser SSH](/features/ssh-bilingual) guides.

Configuration keys, API fields, commands, product names, user-provided values, remote terminal output and original diagnostics retain their spelling. Chinese errors include explanations alongside original diagnostic details. Changing language does not change the time zone or recreate an SSH session.

## Documentation language

Choose **中文** or **EN** in the documentation header. English keeps the original URLs; Chinese pages live under `/zh-CN/`. Archived builds keep their version prefix, for example `/0.8/zh-CN/install/docker`. Switching language keeps the current page, query and fragment. Documentation language follows the URL independently of the application cookie.

Navigation, page content, search results, release history and upgrade notes follow the selected language. Search uses the real bilingual index and filters by language. Chinese headings retain the English reference anchors where the source pages use them. Screenshots reused from upstream are labeled as English screenshots; they are not Chinese interface captures.

In-app documentation buttons continue to open the upstream English site until the maintained documentation site is deployed. Installation examples that use upstream images or flakes are explicitly identified; they do not imply those artifacts contain this fork's translations.

## Maintaining interface translations

Add English messages in `app/i18n/en.ts` and Simplified Chinese in `app/i18n/zh-CN.ts`. Module resources such as `en/machines.ts` and `zh-CN/machines.ts` are re-exported there. TypeScript checks message keys; unit tests check matching interpolation placeholders.

Use `useI18n()` in React and `getLocale(request)` with `translate()` in server actions. Use `Message` for sentences with inline code or styled names so the whole sentence can be reordered. Pass the locale to time formatters. Keep request languages isolated; do not store a user's language in a process-wide variable.

## Maintaining documentation

Keep English source files and their `.zh-CN.md` or `.zh-CN.mdx` counterparts together. Each folder's `meta.json` and `meta.zh-CN.json` define navigation. Use site-path links such as `/install/docker`; the renderer applies the language and React Router adds any version prefix. Keep commands, identifiers and configuration values unchanged. Version values come from `docs/app/lib/versions.ts`.

Use `[#english-anchor]` on translated headings to retain inbound links and language-switch fragments. Update both `CHANGELOG.md` and `CHANGELOG.zh-CN.md`, preserving version headings, dates, references and the `Upgrading`, `Changes`, `Fixes` section markers used by the release parser. The renderer translates those section labels.

Upstream updates open synchronization PRs and a tracking Issue with translation work. Those reminders do not prove that all changed prose has been translated. Review the diff and rerun checks before merging. Precise stale-translation checks, release-line adaptation, Docker publication and Cloudflare deployment remain separate acceptance steps. Deployment configuration is documented in `.github/FORK_SETUP.zh-CN.md` in the repository.
