### Accounts, users and links

Headplane accounts are created at the first SSO or proxy-auth sign-in. A role
controls console permissions. A Headscale user owns machines and auth keys;
linking identifies the account's own resources without changing its role.
Each account links to one Headscale user, and a Headscale user cannot be claimed
by two accounts. Unclaimed users matching the SSO subject or email link
automatically at sign-in and on later visits. See
[Users & roles](/features/users-roles) and
[SSO matching](/features/sso#how-accounts-match-headscale-users).

Select **English** in the header and open **Users**. The page shows role, last
login and machine activity, with a separate list of unlinked Headscale users.
Local accounts remain visible when Headscale is unavailable; a notice explains
why Headscale data and machine information are missing. Group editing is hidden
while the policy cannot be read.

### Create, rename and delete

Select **Add user**, enter a username and optional display name and email, then
choose **Create user**. Names must be at least two characters, start with a
letter and contain letters, decimal digits, dots, hyphens or underscores, with
at most one non-trailing `@`. Unicode letters and decimal digits are supported.
New users appear under **Unlinked Headscale users**.

Use an unlinked user's menu to rename or delete. OIDC-managed users cannot be
renamed. Renaming does not rewrite ACL references. Remove machines or change
their owner before deleting a user. Deletion cannot be undone, and an OIDC
sign-in recreates an OIDC-managed user. Deletion unlinks Headplane accounts
without deleting those login accounts. An account's own row does not offer
deletion of its linked user.

### Link accounts and assign roles

Owners, admins and IT admins select **Link Headscale user** in an account's menu,
choose an unclaimed user and submit. **Change linked user** moves an existing
link, with the current choice marked. Concurrent claims are rejected.
These roles also receive **Link your account** after an unmatched SSO sign-in;
**Skip for now** leaves it for later. Other roles rely on automatic matching or
an administrator, because choosing an arbitrary user would claim their resources.

The first account is the sole owner. Later accounts start as members unless SSO
sets another initial role or supplies role claims. The role capabilities remain:

| Role          | Access                                                                            |
| ------------- | --------------------------------------------------------------------------------- |
| Owner         | Everything, including transferring ownership.                                     |
| Admin         | Everything except transferring ownership.                                         |
| Network Admin | Manage ACLs, DNS and network settings; view machines and users; create auth keys. |
| IT Admin      | Manage machines, users, settings and sign-in restrictions; read ACLs and DNS.     |
| Auditor       | Read all console pages; create their own auth keys.                               |
| Viewer        | View machines and users; create their own auth keys.                              |
| Member        | Device connection home page, without console access.                              |

Choose **Change role** on a linked account. Owner changes require **Transfer
ownership**, performed by the current account owner. The old owner becomes an
admin; only the new owner can transfer it back. An API-key session has full
upstream access but cannot act as the account owner to transfer ownership.

### Groups and member onboarding

**Edit groups** requires both user and policy write permissions and a writable
Headscale `database` policy. Choose existing `group:...` names or enter valid
new ones, then **Save groups**. Membership lives in the policy's `groups`
section. Saving rewrites the policy, preserves other members and removes
comments, with a warning when comments exist. File policies remain read-only;
set `policy.mode` to `database` in Headscale and apply its configuration before
editing groups.

Members see **Connect your devices**, with platform downloads, a Linux install
script and the network's `tailscale up --login-server=...` command. Link status
distinguishes linked accounts, waiting for a first SSO device, and administrator
assistance. Device approval follows the existing Headscale setup. These steps
do not grant dashboard access.

Language selection preserves permissions, version support, form field names,
role IDs, commands, configuration keys, user data and original Headscale
diagnostics. See [Language](/features/language) for browser preferences.
